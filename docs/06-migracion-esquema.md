# 06. Migración del esquema

## Principio

El esquema destino no se genera copiando y pegando el DDL Oracle. Se diseña:
se decide qué se conserva, qué se rediseña y qué se documenta como brecha.
Este laboratorio mantiene la API de negocio, pero cambia la representación
física cuando aporta claridad o rendimiento.

## Orden de ejecución

```text
Oracle (origen)                     EPAS (destino)
─────────────────                   ──────────────
01_types.sql                        01_tables.sql
02_tables.sql                        (carga de datos)
03_sequences.sql                    02_indexes.sql
04_indexes.sql                      03_constraints.sql
05_constraints.sql                  04_views.sql
06_views.sql                        05_materialized_views.sql
07_materialized_views.sql           06_packages.sql
08_packages.sql                     07_standalone.sql
09_standalone.sql                   08_triggers.sql
10_triggers.sql                     09_after_load.sql
11_seed.sql
```

En el destino, las tablas se crean **antes** de la carga; los índices, FKs,
vistas, paquetes y triggers se crean **después**. Esto es intencional:

- `COPY` sin índices es más rápido.
- Los triggers no disparan auditoría durante la carga.
- Las FKs se pueden validar en línea con `NOT VALID` + `VALIDATE CONSTRAINT`.

## 1. Inventario

Antes de escribir DDL:

```bash
make oracle-load
make assess
```

El assessment genera `migration/reports/assessment.md` con tablas, tipos,
índices, objetos PL/SQL, particiones, MVs y riesgos. Úsalo como checklist.

También puedes consultar el diccionario:

```sql
SELECT table_name, column_name, data_type, data_length, char_used
  FROM user_tab_columns
 ORDER BY table_name, column_id;

SELECT index_name, index_type, table_name, uniqueness
  FROM user_indexes
 ORDER BY table_name;
```

## 2. Tablas y columnas

### Ejemplo simple

```sql
-- Oracle
CREATE TABLE regiones (
  region_id NUMBER(3) CONSTRAINT pk_regiones PRIMARY KEY,
  nombre    VARCHAR2(60) NOT NULL,
  codigo    CHAR(2) NOT NULL
);

-- EPAS
CREATE TABLE regiones (
  region_id bigint      CONSTRAINT pk_regiones PRIMARY KEY,
  nombre    varchar(60) NOT NULL,
  codigo    char(2)     NOT NULL
);
```

### Ejemplo con LOB, XML, JSON y generadas

```sql
-- Oracle
CREATE TABLE productos (
  producto_id NUMBER(10) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  precio      NUMBER(12,2) NOT NULL,
  costo       NUMBER(12,2) NOT NULL,
  imagen      BLOB,
  ficha_xml   XMLTYPE,
  atributos   CLOB CHECK (atributos IS JSON),
  margen      NUMBER(12,2) GENERATED ALWAYS AS (precio - costo) VIRTUAL
);

-- EPAS
CREATE TABLE productos (
  producto_id bigint        GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  precio      numeric(12,2) NOT NULL,
  costo       numeric(12,2) NOT NULL,
  imagen      bytea,
  ficha_xml   xml,
  atributos   jsonb CHECK (jsonb_typeof(atributos) = 'object'),
  margen      numeric(12,2) GENERATED ALWAYS AS (precio - costo) STORED
);
```

## 3. Objetos y colecciones

### Objeto `t_direccion`

No se migra como columna de objeto. Se aplana:

```sql
-- Oracle
direccion t_direccion

-- EPAS
dir_calle  varchar(150),
dir_ciudad varchar(80),
dir_estado varchar(80),
dir_pais   char(2),
dir_cp     varchar(12)
```

Ventajas: se indexa, se consulta y se actualiza sin funciones especiales.
Desventaja: se pierde la agrupación semántica; si la aplicación usa
`direccion.ciudad`, hay que cambiar el acceso.

### Nested table `t_telefonos`

Se convierte en `text[]`:

```sql
-- Oracle
telefonos t_telefonos
-- EPAS
telefonos text[]
```

El ETL transforma `LISTAGG(..., '|')` en un arreglo. Si cada teléfono necesita
atributos, usa una tabla hija en lugar de un arreglo.

## 4. Secuencias e identidades

- Secuencias Oracle → secuencias EPAS.
- Identidades Oracle → identidades EPAS.
- Triggers `BEFORE INSERT` que asignan `NEXTVAL` → triggers con `nextval()`.
- Después de la carga, `setval` al máximo + 1.

```sql
-- Oracle
CREATE SEQUENCE seq_clientes START WITH 1 INCREMENT BY 1 CACHE 20;

-- EPAS
CREATE SEQUENCE seq_clientes START WITH 1 INCREMENT BY 1;
```

```sql
-- Oracle
:NEW.cliente_id := seq_clientes.NEXTVAL;

-- EPAS
:NEW.cliente_id := nextval('seq_clientes');
```

El `09_after_load.sql` resincroniza secuencias e identidades. No lo omitas.

## 5. Restricciones

### FKs después de la carga

```sql
ALTER TABLE pedidos
  ADD CONSTRAINT fk_pedidos_cliente
  FOREIGN KEY (cliente_id) REFERENCES clientes (cliente_id)
  NOT VALID;

ALTER TABLE pedidos
  VALIDATE CONSTRAINT fk_pedidos_cliente;
```

Ventajas:

- La creación es rápida (solo metadatos).
- La validación usa un lock más débil que un `ALTER TABLE ... ADD ... VALID`.
- Si hay huérfanos, la validación falla y sabes exactamente qué corregir.

### Restricciones diferidas

```sql
-- Oracle
FOREIGN KEY (empleado_id) REFERENCES empleados (empleado_id)
  DEFERRABLE INITIALLY DEFERRED

-- EPAS
FOREIGN KEY (empleado_id) REFERENCES empleados (empleado_id)
  DEFERRABLE INITIALLY DEFERRED
```

Útil cuando un pedido y su detalle se insertan en la misma transacción sin
orden estricto.

### Checks

`CHECK` se traduce casi directo. Cambios frecuentes:

| Oracle | EPAS |
|---|---|
| `REGEXP_LIKE(col, '^[A-Z]+$')` | `col ~ '^[A-Z]+$'` |
| `col IS JSON` | `jsonb_typeof(col) = 'object'` |
| `NVL(col, 0) > 0` | `COALESCE(col, 0) > 0` |
| `SYSDATE` | `CURRENT_DATE` / `CURRENT_TIMESTAMP` |

## 6. Índices

| Oracle | EPAS |
|---|---|
| B-tree | btree |
| `UPPER(email)` | `(upper(email))` |
| `CASE WHEN activo='S' THEN precio END` | índice parcial `WHERE activo='S'` |
| Bitmap | btree / BRIN / parcial |
| IOT | PK + `CLUSTER` |
| Reverse key | sin equivalente directo |
| Invisible | sin equivalente; usar `hypopg` o separar esquema |
| `INCLUDE` (no Oracle) | `INCLUDE` (EPAS) |

En el laboratorio:

```sql
CREATE UNIQUE INDEX uq_clientes_email ON clientes (upper(email));
CREATE INDEX ix_productos_activos_precio ON productos (precio) WHERE activo = 'S';
CREATE INDEX ix_pedidos_estado_include ON pedidos (estado) INCLUDE (cliente_id, total);
CREATE INDEX ix_clientes_telefonos_gin ON clientes USING gin (telefonos);
```

Los índices se crean después de la carga. En producción, evalúa
`CREATE INDEX CONCURRENTLY` para no bloquear escrituras (no puede ejecutarse
dentro de una transacción).

## 7. Vistas y vistas materializadas

### Vistas

La mayoría se traducen directo. Cambios típicos:

```sql
-- Oracle
SELECT c.direccion.ciudad AS ciudad FROM clientes c;
-- EPAS
SELECT c.dir_ciudad AS ciudad FROM clientes c;
```

```sql
-- Oracle
SELECT TO_CHAR(TRUNC(fecha_pedido,'MM'),'YYYY-MM') ...
-- EPAS
SELECT to_char(date_trunc('month', fecha_pedido),'YYYY-MM') ...
```

`ROWNUM`:

```sql
-- Oracle
SELECT * FROM (SELECT ... ORDER BY fecha DESC) WHERE ROWNUM <= 10;
-- EPAS
SELECT ... ORDER BY fecha DESC LIMIT 10;
```

`CONNECT BY` se conserva en EPAS, pero conviene conocer la alternativa
`WITH RECURSIVE` para código nuevo.

### Vistas materializadas

Oracle `REFRESH COMPLETE ON DEMAND` → EPAS `REFRESH MATERIALIZED VIEW`.
No hay `REFRESH FAST ON COMMIT`. El laboratorio usa refresco completo y un
índice único para permitir `REFRESH ... CONCURRENTLY`.

## 8. Paquetes PL/SQL

EPAS soporta paquetes, `%TYPE`, cursores, excepciones, `PRAGMA
AUTONOMOUS_TRANSACTION`, `RAISE_APPLICATION_ERROR` y `MERGE`. Se conserva la
API:

```sql
-- Oracle
pkg_ventas.crear_pedido(...);
-- EPAS
pkg_ventas.crear_pedido(...);
```

Cambios internos:

| Oracle | EPAS |
|---|---|
| `SYS_REFCURSOR` | `REFCURSOR` |
| `seq.NEXTVAL` | `nextval('seq')` |
| `DBMS_MVIEW.REFRESH` | `REFRESH MATERIALIZED VIEW` |
| `EMPTY_CLOB()` | `''` |
| `USER` | `UPPER(CURRENT_USER)` |
| `DBMS_STATS` | `ANALYZE` |

Los paquetes se ejecutan con `edb-psql`. Un `psql` genérico puede fallar al
parsear bloques `CREATE PACKAGE` sin `/`.

## 9. Triggers

La sintaxis Oracle se conserva en EPAS:

```sql
CREATE TRIGGER trg_pedido_detalle_biu
BEFORE INSERT OR UPDATE ON pedido_detalle
FOR EACH ROW
BEGIN
  :NEW.total_linea := ROUND(:NEW.cantidad * :NEW.precio_unitario, 2);
END;
```

Los triggers se crean **después** de la carga para no duplicar auditoría.
Diferencias a revisar:

- `COMPOUND TRIGGER` no tiene equivalente directo.
- `INSTEAD OF` y `FOLLOWS` requieren pruebas.
- Los triggers de statement no son iguales en todos los casos.
- Un trigger `AFTER` que escribe con transacción autónoma debe probarse bajo
  carga.

## 10. Esquema y `search_path`

Oracle separa por usuario/esquema. EPAS usa esquemas dentro de una base:

```sql
CREATE SCHEMA ventas AUTHORIZATION ventas;
ALTER DATABASE ventas SET search_path TO ventas, public;
```

El usuario `ventas` es dueño del esquema. Los scripts hacen
`SET search_path TO ventas, public;` para no calificar cada objeto.

## 11. Compatibilidad Redwood

EPAS expone parámetros que imitan comportamiento Oracle:

| Parámetro | Efecto | Valor en el laboratorio |
|---|---|---|
| `edb_redwood_date` | `DATE` se comporta como timestamp | `on` |
| `edb_redwood_strings` | Comparaciones de cadenas estilo Oracle | `on` |
| `edb_redwood_raw_names` | Nombres de columnas en mayúsculas | `off` |

No actives todo sin entender el impacto. En el laboratorio se usan tipos
explícitos (`timestamp(0)`) para no depender del parámetro, y se documenta
`edb_redwood_date` como red de seguridad.

## 12. Compilación y validación de objetos

```bash
# Cargar paquetes y triggers en EPAS
docker compose --env-file .env -f docker/compose.yaml exec -T edb \
  edb-psql -X -v ON_ERROR_STOP=1 -U ventas -d ventas -f - \
  < sql/edb/06_packages.sql
```

Comprobar objetos inválidos en Oracle:

```sql
SELECT object_name, object_type, status
  FROM user_objects
 WHERE status <> 'VALID';
```

En EPAS:

```sql
SELECT n.nspname, p.proname, p.prokind
  FROM pg_proc p JOIN pg_namespace n ON n.oid = p.pronamespace
 WHERE n.nspname = 'ventas'
 ORDER BY 2;
```

## 13. Decisiones documentadas del laboratorio

1. **Dirección plana** en lugar de objeto: indexable y simple.
2. **`text[]`** en lugar de nested table: conserva orden y permite GIN.
3. **`jsonb`** en lugar de CLOB JSON: mejor consulta y validación.
4. **`xml`** en lugar de XMLTYPE: tipo nativo, sin funciones Oracle.
5. **`timestamp(0)`** para `DATE`: preserva la hora.
6. **`bytea`** para BLOB/RAW: suficiente para el volumen del lab.
7. **Paquetes** en EPAS: conserva la API y demuestra compatibilidad.
8. **Índices/FKs después de la carga**: rendimiento y locks.
9. **Triggers después de la carga**: evita auditoría duplicada.
10. **Resync de secuencias**: evita colisiones de PK.
